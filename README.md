# DataRelay

FUJITSU Interstage Navigator（SymfoNavi）からデータを取り出し、
**SQLite3 / CSV / TXT / EXCEL / ACCESS** のファイルとして、決まった場所へ決まった時刻に置き続けるための Windows 用アプリです。

ブラウザーで操作します（Flask + ローカルサーバー、`http://127.0.0.1:5031`）。

- 取り出す元は3種類 ―― **RNE**（Navigator への問い合わせ）、**固定長テキスト**（手元のファイルを位置で切る）、**結合**（複数ファイルをキーで繋ぐ）
- 取り出したあとの道は3種類とも同じ ―― 変換 → 公開（差し替え）→ 控え（世代バックアップ）
- 予定を組めば、画面を開いていなくても自動で走ります（通知領域に常駐）

## できること

### 対象を登録して、まとめて実行する

「何を、どこから読んで、どこへ、どの形式で出すか」を1件ずつ登録します（＝**対象**）。
一覧から選んで実行、または全件実行。実行中は1件ごとの進捗・成否が画面に出ます。

入力は3種類です。

| 入力 | 何をするか | 使うもの |
|---|---|---|
| **RNE** | Navigator へ問い合わせて表を受け取る | Navigator API（既定）または DDE |
| **固定長テキスト** | 手元のテキストを「何文字目から何文字」で切って列にする | **読取マスタ** |
| **結合** | 複数のファイルをキーで突き合わせて1つの表にする | **結合マスタ** |

出力は **SQLite3 / CSV / TXT / EXCEL(xlsx) / ACCESS(accdb)**。同時に複数の形式を出すこともできます。

### 自動実行（カレンダー）

対象ごとに実行ルールを持たせます。種類は **毎日 / 平日 / 毎月（日指定）/ 特定日 / 一定間隔（分）**。
カレンダー画面で「これから走る予定」と「走った実績」を見比べられます。

### 読取マスタ・結合マスタ

- **読取マスタ** … 固定長テキストの切り方に名前を付けて保存。同じ形式のファイルが何本あってもマスタは1つで足ります。
- **結合マスタ** … 繋ぎ方（どのファイルの、どの列で繋ぐか）に名前を付けて保存。走らせる前に「このつなぎ目で何件一致するか」を数えて見せるので、キーの取り違えで 0 件・件数の膨張が起きたまま出来上がることを防げます。

どちらも **EXCEL / JSON で書き出し・取り込み**できます（列定義が数百行になる読取マスタは、EXCEL で編集して戻すのが現実的なため）。

### データビュワー

出来上がったファイル（SQLite3 / CSV / TXT / EXCEL / ACCESS）を、アプリの中でそのまま開けます。

- **データ一覧** … 検索・ページ送り
- **集計表** … 列をドラッグして行・列・値へ配置（カウント／合計／平均／最小／最大、小計・総計）
- **グラフ** … 縦棒／横棒／折れ線

共有フォルダー上のファイルは、いったんローカルへ写してから読みます。
共有の実体を開いたままにしないので、**見ている最中に公開（差し替え）が失敗する**ことがありません。

### 安全に置き換える（公開）

出力先は多くの場合ネットワーク共有で、他のアプリが読んでいる最中かもしれません。

1. いったん隠しファイルへ最後まで書く
2. 大きさを照合する
3. `os.replace` で一気に差し替える

差し替えられなかったときは `*.pending_*` として残し、次の実行のはじめに適用します。

**0件保護**（抽出結果が 0 行なら公開しない）と**世代バックアップ**（既定 3 世代）は共通設定で切り替えます。

### 持ち出し・持ち込み

登録した内容（**対象の登録／自動実行の予定／読取マスタ／結合マスタ**）を1つの ZIP にまとめて書き出し、別の PC で戻せます。
中身は素の JSON なので、ZIP を開けばそのまま読めます。

結び直しは **名前**で行います（id は持ち出しません）。
共通設定（パス・接続先・控えの置き場所）は PC ごとに違うので持ち出しません。

### 診断・ログ

- **事前診断** … 「設定した場所は在るか」「いまの抽出方式でそれは要るのか」「データは新しいか」「API は使える状態か」を読むだけで確かめます。赤くするのは *いま要るのに使えないもの* だけです。
- **アプリ監視** … ブラウザーとサーバーのハートビート、往復時間、再接続回数
- **実行ログ** … 画面から全体コピー／最新実行のみコピー／消去

## 必要なもの

- **Windows**（ランチャー・通知領域・DDE・DLL 呼び出しがすべて Windows 前提です）
- **Python 3**（PATH が通っていること。`py` または `python` で起動します）
- 依存パッケージ（`config/requirements.txt`）

  ```
  Flask>=3.0,<4
  pywin32>=306
  xlrd>=2.0.1
  openpyxl>=3.1
  ```

  RNE を使う場合のみ、加えて次のどちらかが必要です。

  - **Navigator API（既定）** … `SymNaviA.dll`。`C:\NAVIAP` 配下の **Python と bit 数が一致する** DLL を最優先で探します。見つからないときだけ、同梱の `Config\NAVIAP` を探します。
  - **DDE 互換方式** … `SymNavi.exe`（既定 `C:\NAVICL\bin\SymNavi.exe`）と `symnavim.def`

固定長テキストと結合だけを使うなら、Navigator への接続は要りません（Flask があれば動きます）。

## はじめかた

### 1. 接続情報を用意する

`config/symnavim.conf.sample` を同じフォルダーへ `symnavim.conf` として複製し、実際の値を書きます。

```ini
[Connect_例]
SymNaviServer=＜Navigator Server 名＞
SymNaviUSERID=＜利用者ID＞
SymNaviPASSWD=＜パスワード＞
CatalogDBMSList=SYMFOWARE/RDB
```

`symnavim.conf` は **リポジトリで追跡しません**（`.gitignore`）。認証情報は PC・環境ごとに違うためです。
文字コードは CP932 / UTF-8 のどちらでも読めます。

### 2. 起動する

| 方法 | 使うもの |
|---|---|
| ダブルクリック（推奨） | `start.vbs` |
| コマンドプロンプトから | `start.bat` |
| Python から | `py start_app.py` |

初回は不足パッケージを `pip install --user` で入れてから起動します（`start.bat`）。
起動するとブラウザーが `http://127.0.0.1:5031` を開きます。

> **`python app.py` の直接起動はできません。**
> 起動の見張り役（`lib/launch_guard.py`）を通さないと多重起動の防止・ローカル領域の準備が行われないため、拒否します。

### 3. 対象を登録する

「対象ファイル」画面から登録します。設定の実体は
`Config/app_settings.sqlite3` に入ります（これも追跡しません ―― 現場で登録したものが、更新のたびに配布時点へ戻ってしまうため）。
マスターが無い環境では `config/app_settings.template.sqlite3` を複製して始めます。

## 設定ファイル

| ファイル | 中身 | 追跡 |
|---|---|---|
| `config/symnavim.conf` | Navigator への接続先・認証情報 | しない |
| `Config/app_settings.sqlite3` | 登録した対象・予定・共通設定・実績 | しない |
| `config/symnavim.conf.sample` | 接続設定のひな形 | する |
| `config/app_settings.template.sqlite3` | 設定 DB の初期値 | する |
| `config/config.json` | 旧形式の設定（移行元として読みます） | する |
| `config/requirements.txt` | 依存パッケージ | する |
| `config/rne/` | RNE ファイルの既定の置き場所 | する |
| `config/NAVIAP/` | `SymNaviA.dll`（ローカルに無いときのフォールバック） | する |
| `config/docs/Navigator_API.md` | Navigator API リファレンス（画面から読めます） | する |

> Windows では `config/` と `Config/` は同じ場所を指します。`.gitignore` には両方の綴りを書いてあります。

## 画面の構成

| 画面 | 何をするところか |
|---|---|
| **対象ファイル** | 対象の登録・編集・実行。検索、状態（有効／無効）、予定の有無、並び順で絞り込み |
| **カレンダー** | 自動実行の予定と実績 |

読取マスタ・結合マスタは、それぞれ専用の管理画面を持ちます（新規作成／EXCEL・JSON での書き出し・取り込み）。

## 動きの仕組み

### 同時に流す

RNE は Navigator の応答待ち、固定長テキストと結合は手元（共有フォルダー）の読み書き待ちで、**待つ相手が違います**。
互いの材料にならないものは同時に流します。

```
RNE      ━━━━━━━━━━━━━━━━━━━  （既定 6 ライン、最大 24）
テキスト ━━━━━━━━            （自動では最大 4 ライン）
結合            ━━━━━━━━━    （材料がそろってから）
```

割り当ての判断は `lib/navi_lane.py` にあり、時計もスレッドもファイルも触りません（＝実際に走らせずに確かめられます）。
実際に流す係は `lib/navi_lanerun.py` です。

### 順番と待ち合わせ

結合は、ほかの対象が作ったファイルを材料にすることがあります。そこで走る前に材料の様子を見ます。

- いま作っている最中か（このアプリで実行中／公開の途中）
- もうすぐ作り始めるか（先読みの時間内に予定があるか）

どちらかなら待ちます。どちらでもなければ走ります（`lib/navi_order.py`）。
順番を無視すると、**正しい形をした、中身が1回ぶん古いファイル**が出来上がります ―― これは誰も気づけません。

### 落ちても巻き込まない

`SymNaviA.dll` の読み込みで異常終了しても、落ちるのは切り離した子プロセスだけです。
RNE の読み取りも DLL の診断も、本体とは別のプロセスで行います。
本体は生き残り、画面には原因の候補（依存 DLL／Visual C++ ランタイム）まで出ます。

### 場所を設定に固定しない

設定は共有（BOX）のマスターを通じて別の PC へも配られます。そこへ絶対パスのまま
`C:\Users\<作った人>\AppData\Local\...` を書くと、別の PC では他人のプロファイルを指してしまいます。
PC ごとに変わる場所は `<PC>` という印で持ち、使うときに実体へ直します（`lib/navi_paths.py`）。

## フォルダー構成

直下に置くのは「起動するもの」だけです。アプリの中身は `lib/` にまとめてあります。

```
DataRelay/
├─ start.vbs / start.bat     Windowsからの起動
├─ start_app.py              Pythonからの起動（lib/launch_guard.py を呼びます）
├─ stop_app.bat              停止（lib/process_manager.py を呼びます）
├─ app.py                    アプリ本体（Flask・設定・ジョブ・予定・抽出）
├─ loading.html              起動待ちの画面（start.vbs が読みます）
├─ templates/ static/        画面（index.html / app.css / app.js）
├─ config/ Config/           設定と接続情報
├─ assets/                   付属ファイル（空のACCESSひな形など）
└─ lib/                      アプリの中身
```

`app.py` と `start_app.py` が起動時に `lib/` を探し先へ足すので、コードの `import` は分ける前と同じです。

### `lib/` の中身

| ファイル | 役割 |
|---|---|
| `launch_guard.py` | 起動の見張りと多重起動の防止。ブラウザー起動、ランチャーログ |
| `navi_web.py` | HTTP 層。画面からの求めに応える受け口だけ（処理は本体） |
| `navigator_api.py` | Navigator API 連携。DLL 読み込み、API 定数、DLL 診断、RNE 実行 |
| `api_worker.py` | Navigator API の並列ワーカー（別プロセス） |
| `navi_lane.py` / `navi_lanerun.py` | 何をどの順で、いくつ同時に流すか ／ 実際に流す係 |
| `navi_order.py` / `navi_orderrun.py` | 結合の順番と待ち合わせの判断 ／ 本体の様子を渡す係 |
| `navi_text.py` / `navi_textrun.py` | 固定長テキストの切り方 ／ 読取マスタの出し入れと実行 |
| `navi_join.py` / `navi_joinrun.py` | 結合の組み立て（SQLite で突き合わせ）／ 結合マスタの出し入れと読み手 |
| `navi_split.py` | 列分割・行分割の試し打ちと設計（本番の実行経路には入りません） |
| `navi_output.py` | 出力形式の読み替え・拡張子・食い違い検査 |
| `navi_xlsx.py` | XLSX の書き出しと検査（ZIP/XML として直接組み立て） |
| `navi_publish.py` | 公開 ―― 安全な差し替えと保留の適用 |
| `navi_localcopy.py` | 共有のファイルをローカルへ写してから読む |
| `navi_book.py` | マスタを EXCEL で出し入れする |
| `navi_bundle.py` | 登録内容の持ち出し・持ち込み（ZIP／部分） |
| `navi_paths.py` | PC ごとに変わる場所を設定に固定しない |
| `navi_log.py` | ログの機構（出す・省略する・末尾だけ読む・世代を押し出す） |
| `navi_diag.py` | 事前診断（読むだけ。実行中の状態を書き換えません） |
| `navi_version.py` / `navi_changelog.py` | 版の定数 ／ 更新履歴と同梱仕様書 |
| `tray_icon.py` | 通知領域の常駐アイコン（Windows専用・pywin32のみ） |
| `process_manager.py` | 停止処理（終了 API とプロセス終了） |

### 呼び出し関係

```
start_app.py
  └─ launch_guard.py
       └─ app.py
            ├─ navi_web.py（受け口）
            ├─ navigator_api.py
            ├─ api_worker.py（別プロセス）
            └─ templates/ static/

process_manager.py
  └─ app.py が公開する終了API・実行中プロセス
```

## 実行時に使う場所

### アプリ配置フォルダー

```
<アプリ配置フォルダ>/
├─ Config/
│  ├─ app_settings.sqlite3      設定の実体（マスター）
│  ├─ rne/                      RNEファイル
│  └─ NAVIAP/                   Navigator API DLL（フォールバック）
├─ runtime/app_instance.json    実行中インスタンス情報
└─ logs/launcher.log            ランチャーのログ
```

### ローカル領域（`%LOCALAPPDATA%\DataRelay\`）

共有の上に書かないことで、起動と実行を速くしています。

```
%LOCALAPPDATA%\DataRelay\
├─ runtime\    PID情報・API診断キャッシュ・version.txt
├─ cache\      設定DBの手元の写し
├─ logs\       launcher.log・app.log・crash.log
├─ pycache\    Pythonバイトコードキャッシュ
├─ backup\     ユーザー別バックアップの既定先
└─ dde_work等  一時処理領域（終了時・次回起動時に削除）
```

## 止めかた

- 画面右上の **終了**（終わり方を選べます）
- `stop_app.bat`

ブラウザーのタブを閉じても、自動実行の予定や実行キューが残っていれば常駐を続けます。
そのときは通知領域のアイコンから画面を開く／終了できます。

タブを閉じただけで、走らせるものが何も無いときは自プロセスを終了します（閉じ忘れによるゾンビ化の防止）。

## 困ったときは

| 症状 | 見るところ |
|---|---|
| 起動しない | `logs\startup.log`、`%LOCALAPPDATA%\DataRelay\logs\launcher.log` |
| 突然落ちた | `%LOCALAPPDATA%\DataRelay\logs\crash.log`（DLL 由来の異常終了はここにだけ残ります） |
| 「既存の起動処理が残っています」 | `stop_app.bat` を実行してから起動し直します |
| 設定した場所が使えない | 「ログ・診断」→ **事前診断** |
| DLL が読めない | 「共通設定」→ **抽出方式** →「いま確認する」 |
| 出力が更新されない | 公開の保留（`*.pending_*`）が残っていないか。次の実行のはじめに適用されます |

> **自分自身への問い合わせはプロキシを通しません。**
> `127.0.0.1` が Windows のインターネットオプションの例外一覧に無い端末では、
> 自分自身への確認まで社内プロキシへ送られて失敗します。ランチャー・本体の自己確認・停止ツールの
> 3か所すべてでプロキシを迂回しています。
