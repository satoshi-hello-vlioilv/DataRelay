DataRelay 現行フォルダ・ファイル構成

【置き場所の決まり】(v1.84.0・入口は v1.96.0 から DataRelay.exe だけ)

  直下に置くのは入口と窓口だけです。アプリの中身は lib/ にまとめてあります。

  <直下>
    DataRelay.exe         ... 入口（desktop/ から作る。リポジトリには入れず、Release の DataRelay.zip で配る）
    sidecar.py            ... 窓口（標準入出力で app.py を呼ぶ。ポートを開かない）
    install_local.cmd     ... exe だけを手元（%LOCALAPPDATA%\DataRelay\bin）に置く。中身は共有から読む (v1.97.0)
    app.py                ... アプリ本体（直接の起動はできません。DataRelay.exe から）
    templates/ static/    ... 画面
    config/ Config/       ... 設定と接続情報
    assets/               ... 付属ファイル

  <作る側・確かめる側だけが使うもの（配る zip には入らない。.gitattributes の export-ignore）>
    desktop/              ... 窓（Tauri・Rust）。cargo build --release で DataRelay.exe を作る
    samples/              ... 検証用の見本（RNEなど）。実行では読みません (v1.93.0)
                              本番のRNE置き場(config/rne/)と混ぜると、見本が対象として出てしまうため分けています
    migration/            ... デスクトップ版への移行の記録（報告書 migration/FEASIBILITY.md と移行先の割り当て）
    tests/                ... 検証（python -m unittest discover -s tests -t .）
    .github/              ... Windows で exe を作って自己診断し、main に入ったら Release に置く

  <lib/>
    アプリの中身です。取り込むときの名前は分ける前と同じで、
    app.py が起動時に lib/ を探し先へ足しています。
    そのため、コードの import は1行も変わっていません。

  (v1.96.0 で外したもの: start.vbs・start.bat・start_app.py・stop_app.bat・loading.html・
   lib/launch_guard.py・lib/process_manager.py・lib/tray_icon.py。役目は DataRelay.exe が引き継いだ)

【各ファイルの役割】

■ DataRelay.exe（desktop/）
  入口の窓です。Python を探し（Flask が無ければ初回に入れる）、sidecar.py を子として起こして
  標準入出力で問い合わせます。画面のひな形と静的ファイル・ファイル選択・保存ダイアログ・
  エクスプローラーで開く・通知領域・常駐（× の判断）・Windows の通知・中身の監督（止まったらすぐ起こし直す）を持ちます。

■ sidecar.py
  窓口です。app.py の Flask をサーバーとしては起こさず、WSGI のまま呼びます。
  起動時に app.boot_app() でスケジューラーなどを起こし、入力が閉じたら自分で終わります。

■ app.py
  Flaskアプリ本体です（サーバーとしては動かず、窓口から呼ばれます）。
  APIエンドポイント、設定管理、ジョブ管理、スケジュール処理、
  データ抽出、診断、バックアップ、データビュワーなどの主要機能を持ちます。
  現在の構成では、バックエンド処理の多くがこの1ファイルに集約されています。

■ navi_bundle.py
  登録した中身の持ち出しと持ち込み（一式ZIP／部分）の決まりを持ちます。
  対象の登録・自動実行の予定・読取マスタ・結合マスタを、どういう形で書き出し、
  どう読み戻すか。DBも画面も時計も触らないので、実際に走らせずに確かめられます。

■ navi_crosstab.py
  集計表（表頭あり）RNEの読み方を持ちます。(v1.93.0)
  RNEの末尾にある配置表から 表側・表頭・データ項目 を読み、中間ファイルの段になった見出しを
  1段に畳みます（データ項目の列は「名前#表頭の値」、重なれば _2, _3 …）。ファイルと行を受け取るだけなので、
  実機なしで tests/test_crosstab.py から確かめられます。

■ navigator_api.py
  SymfoNavi Navigator APIとの連携処理を担当します。
  SymNaviA.dllの読み込み、API定数、DLL診断、RNE実行、
  時間型管理ポイントの期間変更などを扱います。

■ api_worker.py
  Navigator APIの並列処理用ワーカーです。
  app.py の process_api_parallel_job() を呼び出し、
  個別ジョブの処理結果をJSONファイルへ安全に書き込みます。

■ index.html
  Web画面全体の構造を定義するHTMLファイルです。
  対象ファイル一覧、カレンダー、データビュワー、共通設定、
  ログ・診断などの画面要素を含みます。

■ app.css
  Web画面全体のレイアウト、配色、余白、ボタン、一覧、モーダル、
  データビュワー、設定画面などの表示スタイルを定義します。

■ app.js
  Web画面の操作とFlask APIとの通信を担当します。
  一覧表示、設定編集、進捗表示、ドラッグ＆ドロップ、カレンダー、
  データビュワー、診断、アプリ監視などのフロントエンド処理を含みます。


【現在の主な呼び出し関係】

DataRelay.exe（窓・Rust）
  └─ sidecar.py（標準入出力の窓口）
       └─ app.py
            ├─ navi_web.py（受け口）
            ├─ navigator_api.py
            └─ api_worker.py（別プロセス）
                 └─ app.py 内の並列ジョブ処理
  画面（index.html・app.css・app.js）は窓がディスクから直接返す


【実行時に使用または生成される主なフォルダ】

<アプリ配置フォルダ>/
└─ Config/
   ├─ app_settings.sqlite3
   ├─ rne/                 RNEファイル配置先として使用
   └─ NAVIAP/              Navigator API関連DLLの配置先として使用


【ローカル実行領域】
%LOCALAPPDATA%\DataRelay\
├─ runtime\             中身の錠（app.lock）・API診断キャッシュ
├─ logs\                desktop.log（窓）・app.log（中身）・crash.log・sidecar_stderr.log・pip_install.log
├─ pycache\             Pythonバイトコードキャッシュ（置きっぱなし可）
├─ backup\              ユーザー別バックアップ既定先
└─ dde_work等             一時処理領域（終了時・次回起動時に削除）

DLLはC:\NAVIAP配下のPython bit数一致DLLを最優先します。利用可能なローカルDLLがない場合だけ、BOX上のConfig\NAVIAPをフォールバック探索します。
